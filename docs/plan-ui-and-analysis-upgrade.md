# แผนปรับหน้าตาและการใช้งาน Lotto Accounting

วันที่จัดทำ: 12 กันยายน 2569 · สถานะ: เริ่มรอบ A แล้ว — ปรับ UI ร่วมและทางเดินรายละเอียด; รอบ B–D ยังไม่เริ่ม

## เป้าหมายและขอบเขต

- ปรับแอป Next.js บน Vercel ในรีโป lotto-accounting ทั้งโหมดบัญชีและหวย
- คงโทนฟ้าอ่อน–กรมท่าและเอกลักษณ์เดิม เพิ่มความอ่านง่ายและลำดับการใช้งาน
- ให้ตรวจคำตอบได้ตั้งแต่ภาพรวม → กรอบ → สูตร → เดือน → งวด → ข้อมูลต้นทาง
- เพิ่มครบ: ค้นหา/รายการโปรด, ชุดตั้งค่าที่บันทึกไว้, เทียบ 2–4 แบบ, รอบเปลี่ยนสูตร, แผนก่อนเริ่มเดือน, ประวัติและกู้คืน, ค้นหาและส่งออกบัญชี
- เกณฑ์เลือกหลักยังเป็นกำไรรวมสูงสุด แสดง ROI และความเสี่ยงประกอบ
- พัฒนาฝั่ง Vercel นี้เท่านั้น การเพิ่มสูตร 3 ตัวหรือการย้ายหน้าที่เหลือจาก Streamlit เป็นงานอีกขอบเขต
- ไม่เพิ่มการส่ง LINE ตามเวลา การแจ้งเตือนอัตโนมัติ หรือการนำแผนไปแทงอัตโนมัติในแผนนี้

## 0. ตั้งต้นจากเวอร์ชันที่ใช้งานจริง

งาน:
1. ตรวจ main และ deployment ล่าสุด รวมถึงงานที่ยังไม่ commit ก่อนเริ่มแต่ละรอบ
2. ตรวจหน้าบันทึกบัญชี สรุป รายการ เว็บ กรอกผล พอร์ต สูตร และหน้าสมาชิก
3. บันทึกภาพและขั้นตอนของงานหลักบนมือถือ แท็บเล็ต และคอม ทั้งธีมสว่าง/มืด
4. เก็บผลทดสอบ engine เดิมไว้เป็นฐาน และแยกข้อบกพร่องเดิมออกจากสิ่งที่เกิดจากการเปลี่ยนครั้งนี้
5. เตรียมข้อมูลจำลองที่มีผลบวก/ลบ ข้อมูลขาด เดือนยังไม่จบ เลขศูนย์นำหน้า และบัญชีหลายสิทธิ์

ส่งมอบ: รายการปัญหาอ้างอิงแต่ละหน้า + ภาพก่อนปรับ + test baseline

ข้อจำกัดการตรวจ: รอบสำรวจที่ผ่านมา LINE OAuth ถูก auto-review ปฏิเสธ จึงต้องจัดการสิทธิ์เข้าตรวจบัญชีจริงผ่านช่องทางที่อนุญาตก่อน live authenticated QA; ใช้ข้อมูลจำลองทดสอบระหว่างพัฒนาได้โดยไม่ถือว่าเป็นการตรวจข้อมูลจริง

## 1. ออกแบบหน้าตาและทางเดินร่วมกัน

งาน:
1. กำหนดสี ขนาดข้อความ ระยะห่าง ความโค้ง และรูปแบบปุ่มให้ใช้ร่วมกัน
2. ข้อความหลักประมาณ 14–16 px; รายละเอียดรองประมาณ 12–13 px; ตัวเลขสำคัญเด่นกว่าเนื้อหา
3. ข้อความทั่วไปตั้งเป้า contrast อย่างน้อย 4.5:1 และปุ่มหลักมีพื้นที่แตะประมาณ 44×44 px
4. แบ่งพื้นที่เป็นหัวหน้า/บริบทที่เลือก → ผลหลัก → สิ่งที่ทำต่อ → รายละเอียด
5. ทำตัวอย่างหน้าสูตร พอร์ต และบัญชีก่อนขยายไปทุกหน้า
6. ออกแบบสถานะกำลังโหลด ไม่มีข้อมูล ผิดพลาด มีการแก้ค้าง และบันทึกสำเร็จให้เหมือนกัน

ส่งมอบ: ภาพหรือหน้าตัวอย่างพร้อมกดได้ของ 3 งานหลัก + component inventory

เกณฑ์ผ่าน: อ่านค่าและรู้ว่าต้องกดอะไรต่อได้ โดยไม่ต้องเลื่อนอ่านคำอธิบายยาวก่อน; ทุกข้อมูลเดิมยังเข้าถึงได้

## 2. ปรับ UI และการนำทางทุกหน้า

งาน:
1. ปรับ shared styles, ฟอร์ม ปุ่ม แท็บ ตาราง การ์ด และกราฟตามแบบ
2. แสดงหวย/พอร์ตและช่วงที่เลือกไว้ชัดเจน พับตัวเลือกขั้นสูงโดยมีสรุปค่าปัจจุบัน
3. มือถือใช้การ์ดและแผ่นรายละเอียด คอมใช้รายการกับรายละเอียดวางข้างกัน
4. เพิ่มเส้นทางรายละเอียด เช่น กรอบ 5 เดือน → สูตร → กันยายน → รายงวด
5. กลับจากรายละเอียดแล้วคืนสูตร/เดือนและตำแหน่งที่อ่านอยู่; เปลี่ยนบริบทใหม่แล้วล้างผลเก่าที่ไม่ตรง
6. ปรับพื้นที่เมนูล่างและแถบบันทึกให้รองรับ safe area และแป้นพิมพ์
7. เพิ่มการใช้งานด้วยคีย์บอร์ด focus ที่เห็นได้ การคืน focus เมื่อปิดแผ่นรายละเอียด และชื่อที่อ่านโดย screen reader
8. ตรวจการซูมข้อความและยกเลิกข้อจำกัดการขยายที่ขัดกับการอ่าน
9. ใช้คำไทยให้ตรงกันทั้งแอป และให้กดดูคำอธิบาย ROI, DD, train/test ได้

เกณฑ์ผ่าน: ไม่มีข้อความ/ปุ่มหลักถูกตัดในจอ 360, 390, 768 และ 1280 px; เส้นทางเดิมทำงานได้; ตัวเลข engine ไม่เปลี่ยน

ปล่อยรอบ A: UI ร่วมและหน้าใช้งานหลัก หลังผ่าน Preview และ regression

## 3. ค้นหา รายการโปรด ชุดตั้งค่า และฐานประวัติ

งาน:
1. ค้นหาชื่อหวย/ตำแหน่งในหน้าเลือกสูตร รวมกับตัวกรองประเภทเดิม
2. ปักหมุดรายการโปรดและแสดงรายการล่าสุดที่ใช้
3. บันทึกชื่อชุดตั้งค่า: หวย สูตร/ทุกสูตร ช่วงคัดเลือก ช่วงทดสอบ ทุน เงินแทง เรตจ่าย และโหมดวิเคราะห์
4. เปิดใช้ ทำสำเนา เปลี่ยนชื่อ และลบแบบกู้คืนได้ พร้อมแสดงว่าค่าปัจจุบันต่างจากชุดที่บันทึกหรือไม่
5. แยกชุดตั้งค่าออกจากผลการรัน: เปิดชุดเดิมด้วยข้อมูลใหม่ต้องมีวันที่ข้อมูลกำกับ
6. เพิ่มฐานเก็บผู้สร้าง เวอร์ชัน และเหตุการณ์แก้ไขสำหรับข้อมูลใหม่ เพื่อให้ฟังก์ชันประวัติในรอบถัดไปต่อได้
7. ตรวจเจ้าของและสิทธิ์จาก LINE session ที่ server ตรวจแล้ว; ไม่ยึด userId ที่ client ส่งมา
8. ออกแบบ migration แบบเพิ่มสิ่งใหม่ เพื่อให้แอปเวอร์ชันก่อนหน้ายังใช้งานได้

เกณฑ์ผ่าน: เปิดค่าที่บันทึกข้ามอุปกรณ์ได้; ค้นหาและตัวกรองทำงานร่วมกัน; ผู้ใช้ไม่เห็นข้อมูลส่วนตัวของผู้อื่น; ถอนสิทธิ์หวยแล้ว API ต้องปฏิเสธ

## 4. เปรียบเทียบการวิเคราะห์ 2–4 แบบ

งาน:
1. เลือกกรอบ/สูตร/ชุดตั้งค่าเข้าแถบเปรียบเทียบได้สูงสุด 4 แบบ
2. บังคับช่วงประเมินร่วมกันและแสดงทุน เงินแทง และเรตจ่ายของแต่ละแบบชัดเจน
3. เมื่อค่าต้นทุนต่างกัน ให้เลือกปรับเป็นเงื่อนไขเดียวกันหรือแสดงคำกำกับ ไม่เปรียบกำไรเสมือนใช้ทุนเท่ากัน
4. ตารางรวมกำไร ROI ต้นทุน จำนวนงวด จำนวนครั้งที่ถูก Max DD และ loss streak
5. กราฟเส้นทุนซ้อนและผลรายเดือนบนช่วงเดียวกัน พร้อม legend และเครื่องหมายที่ไม่อาศัยสีอย่างเดียว
6. กดแต่ละค่ากลับไปดูรายละเอียดสูตร เดือน รายงวด และข้อมูลต้นทางได้
7. บันทึกกลุ่มที่เปรียบเทียบเพื่อกลับมาเปิดใหม่ได้

เกณฑ์ผ่าน: ยอดและกราฟตรงกับการเปิดแต่ละแบบแยกกัน; การเพิ่ม/ลบตัวเปรียบเทียบไม่เปลี่ยนผลของตัวอื่น; วันที่ที่ใช้วัดตรงกัน

ปล่อยรอบ B: ค้นหา/โปรด/ชุดตั้งค่า + เปรียบเทียบหลายแบบ

## 5. ทดลองรอบเปลี่ยนสูตรทุก 1, 2, 3… เดือน

ต้องแยกสองแนวทางใน UI และข้อมูล:
- A: คงสูตรตลอดรอบ แต่สร้างเลขและเลือกจำนวนเลขใหม่ทุกเดือนจากข้อมูลก่อนเดือนนั้น
- B: คงทั้งสูตร ชุดเลข และจำนวนเลขตลอดรอบ แล้วค่อยเลือกใหม่เมื่อเริ่มรอบถัดไป

งาน:
1. เลือกช่วงประเมินและจำนวนเดือนต่อรอบ; สร้างตัวเลือก 1…N ตามข้อมูลที่มีจริง พร้อมเหตุผลเมื่อข้อมูลไม่พอ
2. ใช้ช่วงประเมินร่วมกันทุก N; รอบสุดท้ายที่ไม่เต็มระยะต้องติดป้าย ไม่ตัดเดือนให้แต่ละแบบได้คนละช่วง
3. ก่อนเริ่มแต่ละรอบ เลือกกรอบและสูตรจากข้อมูลก่อนรอบนั้นเท่านั้น
4. แบบ A ใช้ข้อมูลใหม่ได้เมื่อขึ้นเดือนถัดไป แต่ห้ามเปลี่ยนสูตรกลางรอบ; แบบ B ไม่เปลี่ยนเลขหรือ n กลางรอบ
5. แสดงตารางปฏิทิน: รอบที่เท่าไร วันเริ่ม/สิ้นสุด วันที่เลือก สูตร กรอบ ชุดเลข/จำนวนเลข และผลแต่ละเดือน
6. แสดงกำไร ROI ความเสี่ยง จำนวนครั้งที่เปลี่ยนสูตร และจำนวนครั้งที่เปลี่ยนชุดเลข
7. ถ้าจะเลือก N ที่ดีที่สุด ให้ใช้ช่วงคัดเลือกก่อนหน้าและมีช่วงทดสอบแยก; ตารางที่เรียงจากผลย้อนหลังต้องติดป้ายชัดว่าเป็นการเปรียบเทียบย้อนหลัง
8. ใช้ Worker พร้อมความคืบหน้า ยกเลิกงาน และ cache ตามเวอร์ชันข้อมูล/ค่าตั้ง
9. กดตรวจทุกสูตรที่เป็นผู้สมัคร ณ วันเริ่มรอบ รวมทั้งรายการที่ไม่ชนะ และผลรายงวดได้

เกณฑ์ผ่าน: เปลี่ยนผลอนาคตแล้วสูตรและเลขที่เลือกก่อนหน้ายังเหมือนเดิม; N=1 สอดคล้องกับวิธีรายเดือนเดิมเมื่อใช้เงื่อนไขเดียวกัน; แบบ B ไม่มีเลข/n เปลี่ยนกลางรอบ; ข้ามปีและวันหยุดถูกต้อง

ปล่อยรอบ C: การทดลองรอบเปลี่ยนสูตร แยกจากการแก้แผนใช้งานจริง

## 6. แผนที่บันทึกก่อนเริ่มเดือน และประวัติ/กู้คืน

งานแผน:
1. จากผลวิเคราะห์ สร้างแผนร่างพร้อมชื่อ หวย สูตร กรอบ ชุดเลข n เงินแทง เรต และช่วงที่จะใช้
2. แสดงข้อมูลครบให้ตรวจแล้วกดล็อกแผน เก็บเวลาล็อกและข้อมูลถึงวันที่ใด
3. เก็บเวอร์ชัน engine/สูตร ค่าตั้ง และหลักฐานข้อมูลต้นทางที่สร้างซ้ำได้; hash อย่างเดียวไม่พอถ้าข้อมูลเก่าถูกแก้ ต้องมี snapshot หรือเวอร์ชันต้นทางที่เรียกกลับได้
4. แผนล็อกแล้วแก้ทับไม่ได้ การเปลี่ยนต้องเป็นเวอร์ชันใหม่พร้อมเวลามีผล
5. แผนที่สร้างหลังเริ่มช่วงหรือรู้ผลแล้วติดป้ายย้อนหลัง/จำลอง ไม่อ้างว่าเลือกไว้ล่วงหน้า
6. แสดงผลตามแผนจากงวดที่ทยอยมีข้อมูล พร้อมแยกจากการรัน backtest ใหม่ด้วยค่าปัจจุบัน
7. หากมีการแก้ผลหวยต้นทาง ให้เก็บเหตุการณ์และแยกผลเดิมกับผลหลังแก้ ไม่เปลี่ยนหลักฐานเงียบ ๆ

งานประวัติ:
1. แสดงรายการแก้ไขพอร์ต ชุดเลข แผน และผลหวย: ใคร เมื่อไร เปลี่ยนค่าใด ก่อน/หลัง
2. หน้ากู้คืนแสดงผลที่จะเปลี่ยนและสร้างเวอร์ชันใหม่ ไม่ลบประวัติเดิม
3. ใช้เลขเวอร์ชันกันสองอุปกรณ์บันทึกทับกัน; เมื่อขัดแย้งให้เลือกโหลดค่าล่าสุดหรือเทียบก่อนบันทึก
4. เก็บ baseline ของข้อมูลเดิมตอนเปิดระบบประวัติ; ไม่อ้างว่าสามารถกู้เหตุการณ์ก่อนเริ่มเก็บประวัติได้
5. เปลี่ยนการลบที่เกี่ยวข้องเป็น archive/soft delete ตามขอบเขตที่กู้คืนได้

เกณฑ์ผ่าน: แผนเก่ายังตรวจได้หลังตั้งค่าใหม่; การกู้คืนไม่ทำให้ประวัติหาย; ไม่มีการแก้แผนพอร์ตอัตโนมัติจากหน้าทดลอง; API ตรวจสิทธิ์เจ้าของ/ผู้ดูแลตรงกับระบบเดิม

## 7. ค้นหาบัญชีและส่งออก CSV/Excel

งาน:
1. เพิ่มค้นหายอดเงิน ชื่อเว็บ หมายเหตุ และเลขอ้างอิง ร่วมกับช่วงเวลา/เจ้าของ/ทิศทางเงินเดิม
2. เพิ่มล้างตัวกรองและแสดงตัวกรองที่กำลังมีผล
3. ส่งออกข้อมูลครบทุกหน้าที่ตรงตัวกรอง ไม่ใช่เฉพาะรายการที่โหลดมาบนหน้าจอ
4. CSV และ Excel มีวันที่ เจ้าของ เว็บ ทิศทาง ยอด ธนาคาร หมายเหตุ และเลขอ้างอิง พร้อมยอดรวมและเงื่อนไขการส่งออก
5. รักษาเลขศูนย์นำหน้า วันเวลาไทย และตัวเลขเงิน; ข้อความจากผู้ใช้ต้องไม่กลายเป็นสูตรใน spreadsheet
6. รูปสลิปไม่แนบอัตโนมัติ; หากมีลิงก์รูปต้องใช้สิทธิ์เดิมและไม่เผย secret หรือ URL ส่วนตัวถาวร

เกณฑ์ผ่าน: ยอด/จำนวนแถวในไฟล์ตรงกับผล query ตามตัวกรอง ไม่ขาดเพราะ pagination; ผู้ใช้ส่งออกได้เฉพาะข้อมูลที่มีสิทธิ์ดู

ปล่อยรอบ D: แผน/ประวัติ + ค้นหา/ส่งออกบัญชี โดยแยก PR ย่อยตามขนาดงาน

## 8. เกณฑ์ตรวจและเผยแพร่ทุกครั้ง

1. ทดสอบ unit/integration ตามพฤติกรรมที่เปลี่ยน โดยรักษา regression ของสูตร/อันดับ/walk-forward/พอร์ตตามขอบเขต
2. ทดสอบ UI ด้วยข้อมูลจำลองทั้งข้อมูลครบ/ขาด/ผิดรูป/ไม่มีข้อมูล และผู้ใช้หลายสิทธิ์
3. ทดสอบมือถือ/แท็บเล็ต/คอม ทั้งสว่างและมืด รวม keyboard, zoom, navigation และแป้นพิมพ์มือถือ
4. ตรวจข้ามวัน เดือน ปี leap year วันหยุด partial month และต้นทุน/กำไรรวม
5. ตรวจ API permissions, migration compatibility, concurrent edits และ export scope
6. ผ่าน typecheck และ production build; ตรวจ Vercel Preview ของ commit ที่จะปล่อย
7. สำหรับฐานข้อมูล ตรวจ project/account ให้เป็น lotto-accounting เท่านั้น และทดสอบ migration ในสภาพแวดล้อมที่แยกก่อน production
8. ปล่อย migration ที่รองรับเวอร์ชันเก่าก่อนแอปใหม่; เก็บ checkpoint และแนวทาง rollback ของโค้ด/ข้อมูลก่อนขั้นตอนที่ย้อนกลับยาก
9. รวมเข้า main เมื่อ checks ผ่าน ตรวจ Production deployment, route, assets/Worker และ flow ที่เปลี่ยนจริง
10. ส่งสรุปของที่เปลี่ยน ลิงก์ใช้งาน และข้อจำกัดที่ยังเหลือทุกครั้ง

## ประเด็นที่จะตรวจให้ชัดก่อนลงมือแต่ละส่วน

- สิทธิ์เข้าตรวจ LINE และ Supabase ของบัญชีนี้: เป็นข้อจำกัดการเข้าถึง ไม่ใช่เหตุให้ย้ายไปใช้บัญชีอื่น
- ปริมาณข้อมูลจริงและขนาดหลักฐานที่ต้องเก็บ: วัดก่อนตัดสิน cache/job/storage และประมาณงาน
- สิทธิ์การแชร์ชุดตั้งค่า/แผน: ค่าเริ่มต้นเป็นส่วนตัว; ใช้กติกาผู้ดูแลเดิมสำหรับพอร์ต ไม่เปิดให้ทุกคนอัตโนมัติ
- การเปิดผลแผนที่ล็อก: ใช้หน้าเว็บอ่านผลปัจจุบันก่อน ระบบแจ้งเตือนอัตโนมัติเป็นงานแยก
- ประมาณระยะเวลาเป็นรายชุดหลังจบ A1 และตรวจฐานข้อมูล ไม่กำหนดวันส่งจากสมมติฐานที่ยังไม่ได้ตรวจ
