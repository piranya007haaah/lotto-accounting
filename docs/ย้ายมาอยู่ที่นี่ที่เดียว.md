## มติที่ตกลงกันไว้ (ก.ย. 2569)

แอปหวยเดิม (`piranya007haaah/lottery-app` · Streamlit) **จะถูกยุบ** — ทุกอย่างย้ายมาอยู่แอปนี้
ทีละหน้า จนกว่าจะครบแล้วปิดโปรเจกต์นั้นทิ้ง

```
เครื่องเจ้าของ (scrape ผลหวย) ──┐
                                 ├──► Supabase ◄──► แอปนี้ (Vercel)
Streamlit ── กำลังจะเลิกใช้ ─────┘                    ├ กรอกผลเอง
                                                       ├ พอร์ต
                                                       └ สูตร / สถิติ / สามตัว
```

- **ไม่ทำท่อถาวรจาก Streamlit อีกแล้ว** — ที่เคยคุยกันเรื่องตั้ง Streamlit Secrets
  (`snapshot_url` / `snapshot_secret`) เพื่อให้ปุ่มในหน้า 📝 ส่งข้อมูลให้อัตโนมัติ **ยกเลิก**
  เพราะจะแยกขาดจากกัน ⇒ ข้อมูลเข้ามาทาง **เครื่องเจ้าของยิงตรง** เท่านั้น
- SQLite (`data/lottery.db` ฝั่งโน้น) ลดสถานะเหลือแค่ **ไฟล์ทำงานของ scraper**
  (ตัวที่รู้ว่างวดไหนมีแล้ว จะได้เติมเฉพาะช่องว่าง) ไม่ใช่ "ฐานข้อมูล" อีกต่อไป
- ⚠️ **ยิงเข้า Supabase ผ่าน API ของแอปนี้** (`/api/lottery/datasets` + shared secret)
  **ไม่ใช่ต่อ Postgres ตรง** — จะได้ไม่ต้องเอา `SUPABASE_SERVICE_ROLE_KEY` (คีย์เปิดทั้ง DB)
  ไปวางไว้ในเครื่อง และมีตัวตรวจรูปแบบข้อมูล (zod) คั่นอยู่แล้ว

## ทำต่อจากตรงนี้ — เรียงตามลำดับ

ข้อ 1-2 เดิม (ตั้ง secret · ย้ายข้อมูลขึ้น Supabase) **ทำเสร็จแล้ว 4 ก.ย. 69**

### รอบอัปเดตประจำ (ทำทุกครั้งที่อยากให้ข้อมูลสด)

```bash
cd lottery-app && python3 scripts/refresh_all.py --commit --push
```

scrape เติมงวดที่ขาด → commit `data/lottery.db` → ส่งผลหวยปีนี้ + snapshot พอร์ตขึ้นมาที่นี่
· secret อ่านจาก `~/.config/lottery-app/sync.env` (อยู่นอก repo) ไม่ต้องพิมพ์ทุกรอบ
· **ไม่ push ขึ้น GitHub ให้** — สั่งเองเมื่อพร้อม (บัญชีเคยโดน flag จากกิจกรรมอัตโนมัติ)

### หน้าที่ยังไม่ได้ย้าย (เลือกลำดับได้)

- **หน้ากรอกผลเอง** — ย้ายจาก `pages/10_📝_กรอกผลส่งไลน์.py`
  ⚠️ กติกาสำคัญที่ต้องยกมาด้วย: **เติมเฉพาะช่องว่าง ห้ามทับของเดิม** ·
  index = วันปฏิทินจาก 1 ม.ค. · กรอก 3 ตัวบนแล้ว 2 ตัวบนต้อง derive จาก 2 หลักท้าย
  · ⚠️ ถ้าย้ายมาแล้ว **Supabase จะกลายเป็นแหล่งข้อมูลจริง** ต้องคิดเรื่องส่งกลับไป
  ให้ scraper รู้ว่างวดไหนมีแล้ว (ตอนนี้ SQLite เป็นตัวรู้)
- **หน้าสถิติ / Dashboard** — ความถี่ของ train (ใช้ `formulas.ts` ที่มีอยู่แล้ว)
- **หน้าสามตัว** — ต้องย้ายตาราง `datasets_3d` มาด้วย (ตอนนี้ sync แต่ตาราง 2 ตัว)
  และพอร์ต engine 3 ตัว (`src/formulas3.py`) เป็น TypeScript
- **ส่ง LINE** — ยังอยู่ฝั่ง Streamlit/GitHub Actions ทั้งหมด ยังไม่ได้แตะ

## กติกาที่ต้องยกไปด้วยตอนย้ายหน้า (พลาดแล้วเงียบ)

รวมไว้ที่นี่เพราะเป็นสาเหตุของบั๊กที่มองไม่เห็นด้วยตา — รายละเอียดเต็มอยู่ใน
`CLAUDE.md` ของ `lottery-app`:

1. **index ของ sequence = วันปฏิทินนับจาก 1 ม.ค. ไม่ใช่ "งวดที่"** — วันหยุดกินที่ของมัน
   ⇒ ตัดเดือนต้อง "ปิดวันอื่นเป็น `--`" ห้ามตัดสตริงให้สั้นลง (วันที่จะเลื่อนทั้งเส้น)
2. **จัดอันดับ n_bet บน train เท่านั้น ห้ามใช้ test** (= hindsight ตัวเลขโป่งเกินจริง)
3. **งวดที่ไม่ได้แทง (n=0) ไม่นับเป็นงวดที่แพ้** ตอนคิด win rate / ROI
4. **สีเขียว-แดงของแอปนี้แยกไม่ออกด้วยตาบอดสี** (วัดแล้ว ΔE 5.2 deutan)
   ⇒ บาร์กำไรใช้ **ทิศทาง** (ขวา=กำไร ซ้าย=ขาดทุน) + เครื่องหมาย +/− เป็นตัวบอกความหมาย
5. **ตัวเลขที่ทั้งสองแอปโชว์ต้องตรงกันเป๊ะ** ตราบใดที่ Streamlit ยังอยู่ —
   `npx tsx scripts/formula-check.ts` คือตัวกัน (เทียบกับเฉลยจริงจาก Python 2,460 จุด)
   · เฉลยสร้างใหม่ได้ด้วย `python3 scripts/export_engine_fixture.py` ฝั่งโน้น
